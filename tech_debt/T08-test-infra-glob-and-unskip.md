# T08 — Тест-инфраструктура: починить glob и раскипить signing-тест

- **Приоритет:** 7/10
- **Стадия:** Stage 1
- **Область:** backend
- **Статус:** backlog

## Что не так

1. `backend/package.json` `test:unit` перечисляет тестовые файлы **явным списком**. Любой новый `*.test.ts` молча исключается, пока его не добавят в список вручную — покрытие может тихо сокращаться.
2. `backend/src/services/signing.service.test.ts` L10-11 `describe.skip`ается, когда нет `TEST_DATABASE_URL` — самый рискованный тест (сериализация row-lock, ротация ключей) не идёт в CI.

## Почему это важно

Это «инфраструктурный» долг, который подрывает все остальные задачи вида «добавь тест» (T03, T04, T09, T17): новые тесты не запускаются, а CI даёт ложную уверенность.

## Локализация

- `backend/package.json` — скрипт `test:unit`.
- `backend/src/services/signing.service.test.ts:10-11` — `.skip` по `TEST_DATABASE_URL`.

## Минимальная правка

1. `test:unit` → glob: `bun test src/**/*.test.ts scripts/**/*.test.ts`.
2. Раскип `signing.service.test.ts` вынести в отдельный скрипт/CI-job, которому предоставляется `TEST_DATABASE_URL`.

## Подводные камни

- **Раскип требует тестовой БД** (Postgres). Это инфраструктура, а не код — согласовать, где CI возьмёт `TEST_DATABASE_URL` (локальный docker-compose `localhost:55432` или CI-service). Не городить свою инфраструктуру без необходимости — см. T17, куда перенесён сам раскип-джоб.
- **Glob может подхватить** файлы, которые раньше не запускались и теперь падают (например, тесты, требующие БД). Прогнать glob локально до мержа и поправить «ожившие» тесты.
- **Не менять `test:e2e`/прочие скрипты** — только `test:unit`.

## Приёмочные критерии

1. Новый файл `src/foo/bar.test.ts` подхватывается `test:unit` без правки `package.json`.
2. `signing.service.test.ts` не `.skip`ается при наличии `TEST_DATABASE_URL`.
3. `bun run --cwd backend test:unit` зелёный после перехода на glob.

## Валидация

```bash
bun run --cwd backend test:unit
# проверить: добавить временный тест и убедиться, что он попал в прогон
```
