## Назначение

Этот каталог — техническая передача результатов статического аудита другому агенту. Исходный код в рамках аудита не изменялся. Перед исправлением каждого пункта агент обязан сверить вывод с текущим локальным `HEAD`, потому что рабочая копия может отличаться от проверенного remote snapshot.

## Файлы

1. `01_EXECUTIVE_SUMMARY.md` — краткая оценка состояния и главные риски.
2. `02_FINDINGS.md` — полный реестр проблем с ID, доказательствами и ожидаемым исправлением.
3. `03_REMEDIATION_PLAN.md` — безопасный порядок реализации и зависимости между изменениями.
4. `04_VALIDATION_CHECKLIST.md` — проверка поведения после исправлений.
5. `05_AGENT_PROMPT.md` — готовое задание для агента-исполнителя.
6. `06_TASKS.csv` — машиночитаемый реестр задач для импорта или поэтапного учёта.

## Правила работы с отчётом

- Не исправлять все пункты одним большим diff.
- Сначала повторно подтвердить проблему на текущем коде.
- Для поведения, контрактов, авторизации, платежей и provenance начинать с теста на ожидаемый результат.
- Не ослаблять проверки ради прохождения тестов.
- Не выполнять ротацию production-ключей, миграцию production-данных, публикацию или deployment без отдельного разрешения владельца.
- Сохранять посторонние пользовательские изменения.
- После каждого этапа обновлять статус соответствующих ID и прикладывать фактические результаты проверок.

Аудит выполнен статически через GitHub. Последний Vercel status был успешным, однако это не подтверждает корректность тестов и пользовательских сценариев.
